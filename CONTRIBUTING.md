# Contributing to CrapCleaner

Thank you for your interest in contributing to **CrapCleaner**. We welcome contributions ranging from new cleanup categories and performance optimizations to UI enhancements and bug fixes.

---

## Development Setup

1. **Clone the Repository**:
   ```bash
   git clone https://github.com/PatrickJnr/crapcleaner.git
   cd crapcleaner
   ```

2. **Create a Virtual Environment and Install Dependencies**:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   pip install -e .
   pip install -r requirements-dev.txt
   ```

3. **Run the Application**:
   - GUI mode: `python -m crapcleaner.app`
   - CLI mode: `python -m crapcleaner.cli --scan`

---

## Testing and Code Quality

Before submitting a Pull Request, verify that all tests pass and formatting conforms to project standards:

```bash
# Run test suite
pytest

# Code formatting and linting
black crapcleaner tests
ruff check crapcleaner tests
mypy crapcleaner
```

## Adding a New Cleanup Category

To add support for a new application or cache directory:

1. Locate the appropriate category provider module under `crapcleaner/` (such as `crapcleaner/developer/cleanup.py` or `crapcleaner/apps/cleanup.py`).
2. Add a `CleanupCategory` definition:
   ```python
   from crapcleaner.models.category import CleanupCategory, CacheTarget, SafetyLevel

   categories.append(
       CleanupCategory(
           id="mytool_cache",
           name="MyTool cache",
           group="Developer tools",
           description="Caches generated by MyTool. Safe to delete.",
           safety_level=SafetyLevel.LOW_RISK,
           targets=[
               CacheTarget(path=os.path.join(local, "MyTool", "Cache")),
           ],
       )
   )
   ```
3. Add a unit test in `tests/` confirming the category attributes and safety level.
4. Run `pytest` and `ruff check crapcleaner tests` to verify.

## Pull Request Guidelines

- Keep pull requests focused on a single feature or bug fix.
- Ensure all automated checks and tests pass.
- Adhere to the safety tiers (`SAFE`, `LOW_RISK`, `REVIEW`, `DANGEROUS`). Do not assign `SAFE` to user project files or credentials.
